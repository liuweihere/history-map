# 历史来源分层规范

这份规范回答一个核心问题：

> 什么材料属于 raw，什么材料属于 source page，什么材料才能进入 story bundle？

## 四层结构

### Layer 1: Raw Source

位置：

- `raw/sources/classical-texts/`
- `raw/sources/historical-digests/`
- `raw/sources/teaching-notes/`
- `raw/sources/kids-narration/`

用途：

- 保存最接近原材料的输入
- 允许保留孩子原话、转写误差和家长临场表达
- 不直接承担最终事件结论

### Layer 2: Source Page

位置：

- `wiki/sources/`

用途：

- 把 raw source 整理成可链接、可引用、可被导出器识别的来源页
- 说明这份来源支撑什么断言

### Layer 3: Story Bundle

位置：

- `wiki/entities/events/`
- `wiki/entities/map-layers/`
- `wiki/synthesis/child-stories/`
- `wiki/synthesis/parent-notes/`

用途：

- 形成经过审核的历史叙事骨架、地图叙事和亲子教学结构

### Layer 4: Product Data

位置：

- `06_Exports/json/`

用途：

- 提供给站点运行时使用的稳定数据
- 只能脚本生成，不能手改

## 每个故事节点的最小来源闭环

建议每个故事至少具备：

1. 一份正史或编年来源
2. 一份亲子讲述来源
3. 一份儿童口述或反馈来源

如果故事很关键，再补：

4. 一份原典摘录
5. 一份地图参考来源

## 不建议的做法

- 把 event 页写成史料仓库
- 让前端自己发明故事字段
- 只有孩子口述，没有正史校正
- 只有正史摘要，没有孩子真实反馈
