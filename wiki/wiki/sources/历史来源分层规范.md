# 历史来源分层规范

这份规范回答一个核心问题：

> 什么材料属于 raw，什么材料属于 source page，什么材料才能进入 canonical event/person/place？

## 四层结构

### Layer 1: Raw Source

位置：

- `raw/sources/historical-digests/`
- `raw/sources/kids-narration/`
- 后续可增加：
  - `raw/sources/classics/`
  - `raw/sources/teaching-notes/`
  - `raw/sources/map-references/`

用途：

- 保存最接近原材料的输入
- 不要求产品化表达
- 可以是史料摘要、阅读摘记、亲子原话、地图核对笔记

要求：

- 文件名要能看出时间点和主题
- 不直接承担最终事件结论
- 允许不统一文风，但要可追踪

### Layer 2: Source Page

位置：

- `wiki/sources/`

用途：

- 把 raw source 整理成“可链接、可引用、可被导出器识别”的来源页
- 明确这份来源支持哪些事件、人物、地图或叙事

要求：

- 必须有 `id`
- 必须有 `source_refs`
- 必须有 `sources`
- 必须能说明“这份来源支持什么断言”

### Layer 3: Canonical Knowledge

位置：

- `wiki/entities/`
- `wiki/synthesis/child-stories/`
- `wiki/synthesis/parent-notes/`

用途：

- 形成经过审核的事件、人物、地点、势力、地图计划和叙事页

要求：

- 不直接凭空写结论
- `source_refs` 至少要能指回 source page
- 儿童叙事和家长说明都要能解释自己的来源基础

### Layer 4: Product Data

位置：

- `06_Exports/json/`

用途：

- 提供给站点运行时使用的稳定数据

要求：

- 只能由脚本生成
- 不手改
- 可以携带 provenance 信息，但不承载完整史料正文

## 来源类型分类

### 正史

例如：

- 后汉书
- 三国志
- 史记
- 汉书

用途：

- 事实骨架
- 人物与事件主线
- 时序与政权关系

### 编年史 / 通史

例如：

- 资治通鉴

用途：

- 时间轴
- 因果串联
- 先后关系核对

### 文学来源

例如：

- 三国演义

用途：

- 标注文学生长影响
- 明确“好听的故事”与“正史主线”的区别

### 教学材料

例如：

- 家长讲述
- 亲子讲义

用途：

- 生成儿童可理解的讲法
- 设计问题卡和家长提示

### 学习现场记录

例如：

- 小朋友复述
- 听后反馈

用途：

- 找出真正的认知卡点
- 反向修正儿童讲述与家长说明

## 每个故事节点的最小来源闭环

建议每个节点至少有这三类来源：

1. 一个正史摘要来源
2. 一个亲子讲述 / 教学记录来源
3. 一个儿童反馈来源

以黄巾起义为例：

- 正史摘要：[[184-黄巾起义-史料提要]]
- 教学记录：[[184-黄巾起义-亲子共读记录]]
- 儿童反馈：[[184-黄巾起义-小星星讲述]]

## 不建议的做法

- 一次性导入整部史书全文再慢慢整理
- 让 event 页直接承担所有史料摘录职责
- 把演义内容混进正史摘要
- 站点 JSON 手写修改，绕过 wiki/source 链

## 推荐工作流

1. 在 `raw/sources/` 放入节点相关原材料
2. 在 `wiki/sources/` 建对应来源页
3. 用来源页支撑 canonical event / person / map layer
4. 用 exporter 编译成产品数据
5. 站点只消费编译结果
